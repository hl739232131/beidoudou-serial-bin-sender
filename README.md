# 串口 BIN 文件发送上位机（从机模式）

Windows 桌面 `.exe` 上位机，作为**从机**响应主机请求，通过串口按固定帧格式下发 `.bin` 文件数据。

## 通信流程

1. 主机发送 `A5` 命令，申请每包数据字节数 `N`（`0 < N < 513`）。
2. 从机收到 `A5` 后回复 `5A`：
   - `N` 合法时回复 `0xA5`（已收到）
   - `N` 非法（`N == 0` 或 `N > 512`）时回复 `0x00`（异常）
3. 从机将 `.bin` 文件按 `N` 字节分包，最后一份不足 `N` 时填充 `0xFF`。
4. 主机发送 `A7` 命令，申请第 `x` 个数据包。
5. 从机回复 `7A`，把第 `x` 包数据发送给主机。

## 数据帧格式

每帧结构：

| 字段 | 长度 | 说明 |
|------|------|------|
| 帧头 | 2 字节 | `0xAA 0x55` |
| 字节数 | 2 字节 | 小端序，值 = 命令(1) + 数据(N) + CRC32(4) |
| 命令 | 1 字节 | 见下表 |
| 数据 | N 字节 | 命令相关数据 |
| CRC32 | 4 字节 | 小端序，计算范围为「字节数 + 命令 + 数据」 |

### 命令定义

| 命令 | 方向 | 说明 |
|------|------|------|
| `0xA5` | 主机 → 从机 | 申请下发数据包字节数 `N`；数据段为 `N`（2 字节小端序） |
| `0x5A` | 从机 → 主机 | 回复收到 `A5`；数据段为 1 字节状态：`0xA5` 正常 / `0x00` 异常 |
| `0xA7` | 主机 → 从机 | 申请第 `x` 个数据包；数据段为 `x`（4 字节小端序） |
| `0x7A` | 从机 → 主机 | 下发第 `x` 包数据；数据段为 `x`（4 字节） + 该包 `N` 字节数据 |

## 串口参数

| 参数 | 取值 |
|------|------|
| 波特率 | 默认 `115200`（下拉框可选 9600 / 19200 / 38400 / 57600 / 115200） |
| 数据位 / 校验 / 停止位 | `8 / N / 1`（固定） |
| 写超时 | 2 s |
| 读超时 | 1 s |

## 环境准备

需要 **Python 3.10 及以上**（代码使用了 `X | None` 等新式类型标注与 `tuple[...]` 泛型），
开发与测试环境为 Python 3.12。

```bash
pip install -r requirements.txt
```

## 运行

```bash
python main.py
```

界面操作：
1. 选择串口并点击「打开串口」
2. 加载 `.bin` 文件
3. 上位机进入监听状态，等待主机发送 `A5` / `A7` 命令

## 运行测试

```bash
pip install pytest
python -m pytest tests/ -v
```

测试全部使用假串口（不依赖真实硬件），覆盖帧格式、CRC32 校验、A5/A7 命令处理、分包与填充、
异常 N / 越界 x 等情况。

## 打包成 exe

需在 **Windows** 环境下执行（PyInstaller 在目标平台上打包）：

```bash
python build.py
```

输出：`dist/SerialBinSender.exe`

## 日志

运行时日志保存在 `logs/serial-bin-sender.log`，便于排查问题。日志目录位于程序自身所在目录
（源码运行时为项目目录，打包后为 `.exe` 所在目录），与启动时的工作目录无关。

若该目录不可写（例如装在 `Program Files` 下），会依次退化到：

1. `%LOCALAPPDATA%\SerialBinSender\serial-bin-sender.log`
2. 系统临时目录下的 `SerialBinSender\serial-bin-sender.log`

以上都不可用时程序仍会正常启动，只是日志不落盘。实际生效的日志路径会在启动时
显示在窗口的日志框第一行。串口打开失败、帧解析异常等错误同样会写入日志文件。
